# 3-4. こまったときは — うまくいかないとき

本物の実験では、うまくいかないことがよくあります。メッセージを読んで、一つずつ確かめて、
ためしたことをノートに書いておきましょう。

## よくあるこまりごと

| こまったこと | 確かめること |
|---|---|
| パソコンがボードを見つけない（ポートが出ない） | 充電専用ではなく、データも送れるケーブルですか？ ボードによっては USB のドライバー（**CP210x** か **CH340**。USB の差しこみ口の近くにあるチップで決まります）が必要です |
| 書き込みに失敗する（「Failed to connect」） | 書き込みが始まるときに、ボードの **BOOT** ボタンをおしたままにして、「Writing…」と出たらはなします |
| `No USB serial port found` と出る | R がデータ用のケーブルでつながっていますか？ パソコンの別の USB の口も試しましょう |
| `Several ports found` と出る | ボードが 2 台以上つながっています。`--port <名前>` をつけます（名前は `uv run csi-lab ports` で調べます） |
| `Cannot open <ポート>` と出る | Arduino のシリアルモニタなど、ポートを使っているほかのプログラムを閉じてください |
| `No CSI data for 5 s` と出る | S に電気が入っていて、LED が 1 秒に 1 回点めつしていますか？ 2 台とも、このラボのプログラム（S は `csi_tx`、R は `csi_rx`）を書き込みましたか？ |
| R のシリアルモニタに `# still waiting for csi_tx` と出る | S の電波が R に届いていません。S の電気と LED を確かめ、ボードを近づけ、2 つのプログラムのチャンネル（`WIFI_CHANNEL`、11）が同じか確かめます |
| LED がずっととても速く点めつする | 準備に失敗しています。シリアルモニタ（R は 921600、S は 115200）を開いて、`# ERROR` で始まる行を読みましょう |
| 1 秒あたりのパケットが 90 くらいより少ない | ボードを近づけましょう。よく使われているほかの Wi-Fi の機器や電子レンジからもはなしましょう |

記録が終わると、`capture` は 1 秒あたりのパケットの数と、読みとばしたこわれた行の数を表示します。
こわれた行が少しあるのはふつうです。

## エラーメッセージの読み方

エラーメッセージは、パソコンから「ここがうまくいかなかったよ」というお手紙です。
助けを求めるときは、「動かない」だけでなく、メッセージを **ぜんぶ** コピーしましょう。

> 🤖 **AI に聞いてみよう**
> - 「実行したコマンドと、エラーメッセージの全文はこれです: … どういう意味？ 最初に何を
>   確かめればいい？ 一度にぜんぶ直さずに、一つずつ教えて」
> - 「記録が 1 秒に 60 パケットしかありません。考えられる理由を、ありそうな順にならべて」

## たしかめよう

1. パソコンがボードをまったく見つけません。最初に何をためしますか？
2. `capture` が `Cannot open port` と言います。だれがポートを使っていそうですか？
3. 助けを求めるとき、エラーメッセージをぜんぶコピーするのはなぜですか？

<details><summary>こたえ</summary>

1. 別の USB ケーブル（充電専用かもしれない）。次に USB のドライバー（CP210x か CH340）
2. ほかのプログラム。よくあるのは Arduino のシリアルモニタ
3. どのコマンドか、どのポートか、どの行か、というくわしいことがわかると、手伝う人（や AI）に
   本当に起きたことが伝わるから

</details>
