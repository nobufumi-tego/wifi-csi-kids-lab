# 設計判断の記録（ADR）

「なぜそうしたか」を残す場所。コードを読めば**何をしたか**は分かるが、
**なぜ他の選択肢を捨てたか**は残らない。それを書く。

## 書くとき

判断が後から覆せない、あるいは覆すのに大きなコストがかかるとき。
ライブラリの選定、データの持ち方、外部サービスへの依存など。

逆に、いつでも変えられることは書かない。書くほど読まれなくなる。

## ファイル名

`<4桁の連番>-<英小文字スラッグ>.md` — 例: `0001-baremetal-instead-of-vendor-runtime.md`

**採用後の内容は書き換えない。** 判断が変わったら新しい番号で追加し、
古い方のステータスを「棄却（0007 で置き換え）」に変える。
書き換えると、当時なぜそう考えたかが消える。

## 形

```markdown
# 0001. <決めたことを一文で>

- ステータス: **採用**（YYYY-MM-DD）
- 対象: <どのディレクトリ・機能の話か>

## 背景

何に迫られてこの判断が必要になったか。選択肢を並べる。

## 決定

何を採ったか。断定形で書く。

## 根拠

なぜ。可能なら**実測値**を添える（「速い」ではなく「27ms → 2ms」）。
捨てた選択肢について、何が理由で捨てたかも書く。
```
