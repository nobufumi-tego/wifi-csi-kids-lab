## 1. Wi-Fi は、たくさんの波をならべて送っている

レベル 1 では「Wi-Fi の波」を 1 本のように話しました。本当は、Wi-Fi は自分の使う
チャンネル（20 MHz の幅の周波数）を、細い**車線**にたくさん分けています。車線がたくさんある
高速道路のようなものです。車線 1 本 1 本に小さな波が乗っています。この車線を
**サブキャリア**といいます。このような送り方を **OFDM** といいます。

```
周波数 ->
 |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |
-28 ...            -1   (0)  1              ...          28
                         ^ まん中の車線は使わない
```

となりの車線とは 312.5 kHz はなれています。このリポジトリでは **56 本の車線**を使います。
番号は −28〜−1 と 1〜28 です（まん中の 0 番は使いません）。

車線ごとに周波数が少しずつちがうので、波長も少しずつちがいます。レベル 1 の「干渉」を
思い出してください。同じ部屋の同じ道でも、ある車線では**強め合い**、となりの車線では
**弱め合う**ことがあります。だから、車線ごとにちがう大きさで届くのです。

## 2. では、CSI とは？

**CSI** は **Channel State Information（チャネル状態情報）** の略です。受信機はパケット
（電波で送られる小さなデータのかたまり）を受け取るたびに、それぞれの車線の波がどう届いたかを
測ります。

- **振幅**: 届いた波の大きさ。このリポジトリではこれを使います
- **位相**: 届いた波が、上がり下がりのどのあたりにいるか。これも測れますが、アンテナが 1 本の
  安い受信機（ESP32 など）では、受信機自身のタイミングのずれが混ざってしまい、使いにくいのです。
  ここでは使いません

スマホの Wi-Fi のアンテナマークに使われている **RSSI**（受信信号の強さ）とくらべてみましょう。

| | RSSI | CSI |
|---|---|---|
| 1 パケットあたりの数 | 1 つ（全体の強さ） | 56 こ（車線ごと） |
| たとえると | 「曲全体の音の大きさ」 | 「楽器 1 つ 1 つの音の大きさ」 |
| 分かること | 電波は強い？ | 部屋が電波を**どう**変えた？ |

数が 1 つではなく 56 こあるので、CSI は RSSI では気づけない小さな変化も見つけられます。

## 3. 記録はどんな形？

記録は表になっています。**1 行が 1 パケット**です。送信機は 1 秒に 100 パケット送るので、
30 秒で約 3,000 行になります。

| time_s | rssi_dbm | label | sc-28 | sc-27 | … | sc28 |
|---|---|---|---|---|---|---|
| 0.000 | -52 | walk | 31.0 | 29.4 | … | 25.2 |
| 0.010 | -52 | walk | 30.5 | 29.7 | … | 25.8 |

- `time_s`: 始まってからの秒
- `rssi_dbm`: 電波の強さ（0 に近いほど強い）
- `label`: そのとき何をしていたか
- `sc-28` 〜 `sc28`: それぞれの車線の振幅

### ステップ 1: まねっこの記録を作る

まだ機材がないので、**シミュレーター**を使います。送信機と受信機を 3 m はなして置いた部屋を
まねしてくれます。

```bash
uv sync
uv run csi-lab samples
```

`data/samples/` の中に、次のファイルができます。

|---|---|

| `still.csv` | 人が線からはなれて、じっと座っている |
| `walk.csv` | 人が線を横切って行ったり来たりする |

これは、かんたんなしくみで作った**まねっこ**のデータです。本物の部屋はもっと複雑です。

uv run csi-lab show data/samples/empty.csv

  色が振幅です

- **下:** RSSI

2 つの絵は、どこがちがいますか？ ヒートマップの中の**たてのしま模様**をさがしてみましょう。

## 4. はじめに「正規化」するわけ

ESP32 には、自動で音量を調整するつまみ（**自動利得制御**といいます）があります。
パケットごとに音量を上げたり下げたりして、数が使いやすい大きさになるようにしているのです。
そのため、部屋の中で何も動いていなくても、そのままの振幅はとびはねることがあります。

これを消すために、パケットごとに、56 本の車線の平均で割ります。

```python
from csi_lab.features import normalize_per_packet

norm = normalize_per_packet(rec.amplitude)   # どの行も平均が 1 になる
```

`csi-lab show` のヒートマップは、もうこれをしてあります。残るのは車線どうしの**形**
（どの車線が強くて、どの車線が弱いか）です。部屋や、部屋にいる人が変えるのは、この形なのです。

## たしかめよう

1. このリポジトリでは、1 パケットに車線（サブキャリア）がいくつありますか？
2. RSSI は 1 パケットにつき数が 1 つです。ここでの CSI はいくつですか？
3. 絵にする前に、パケットごとにその平均で割るのはなぜですか？

<details>
<summary>答え</summary>

1. 56 本（−28〜−1 と 1〜28）
2. 56 こ。車線ごとに 1 つずつ振幅がある
3. ESP32 はパケットごとに音量を変える（自動利得制御）から。平均で割ると、そのとびはねが消え、
   車線どうしの形が残る。部屋が変えるのは、この形だから

</details>
