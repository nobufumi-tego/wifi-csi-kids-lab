# レベル 4: 何か動いた？ ― 動きの検出器を作ろう

## このレッスンのゴール

- CSI を見る前に、パケットごとに**正規化**する理由がわかる
- CSI を 1 秒ごとの **「動きの数」** に変えられる
- データから **しきい値** を決めて、検出器がどれくらい当たるかを確かめられる
- **うまくいかない場面** を見つけて、その理由を考えられる

**時間:** 60〜90 分くらい
**必要なもの:** このリポジトリを準備したパソコン（レベル 2）。ハードウェアは要りません。シミュレーターを使います。レベル 3 で基板を作った人は、自分の記録でも試せます。

ノートブック版: [`notebooks/02-motion-detector.ipynb`](../../notebooks/02-motion-detector.ipynb)

## 1. なぜ正規化するの？

ESP32 の受信機には、自動で音量を合わせる「つまみ」（自動利得制御）があります。
このつまみは、部屋で何も動いていなくても、**パケットごとに** 音量を上げ下げします。
そのため、生の振幅は人とは関係のない理由でぴょんぴょん変わります。

そこで、それぞれのパケットを **そのパケット自身の平均** で割ります。すると、どのパケットも平均が 1 になり、
サブキャリアどうしの **形** だけが残ります。人が動くと変わるのは、この形のほうです。

```python
from csi_lab import simulate
from csi_lab.features import normalize_per_packet

rec = simulate("still", duration_s=30, seed=1)
raw_avg = rec.amplitude.mean(axis=1)                    # パケットごとの平均
norm_avg = normalize_per_packet(rec.amplitude).mean(axis=1)

print("正規化前: パケットの平均のゆれ =", raw_avg.std())
print("正規化後: パケットの平均のゆれ =", norm_avg.std())
```

`seed=1` では、正規化前のパケットの平均は標準偏差で約 0.9 ゆれていましたが、正規化後はほぼ 0 になりました。
音量つまみの影響が消えたということです。

> **AI に聞いてみよう**
> 「ESP32 には自動利得制御があります。テレビの音量を例にして、パケットごとに平均で割ると
> なぜ役に立つのかを説明してください。コードは書かずに、わたしに質問しながら教えてください。」

## 2. 1 秒ごとに 1 つの「動きの数」

何も動かなければ、各サブキャリアの値はほとんど変わりません。何かが動くと **ゆれます**。
記録を 1 秒ずつの **窓**（まど）に切り分けて、そのゆれを **標準偏差**（値が平均からどれくらい散らばっているか）で測ります。

```python
from csi_lab import simulate
from csi_lab.features import motion_score

for name in ["empty", "still", "walk", "wave"]:
    rec = simulate(name, duration_s=30, seed=1)
    start_s, motion = motion_score(rec)          # 1 秒の窓ごとに 1 つの数
    print(f"{name:6s} 中央値={sorted(motion)[len(motion)//2]:.4f}  最大={motion.max():.4f}")
```

`window_features` を使うと、窓ごとにもっと多くの数（`motion`、`motion_max`、`spread`、
`rssi_std_db`、`change_rate`）がもらえます。レベル 5 ではこれを全部使います。

## 3. しきい値はデータから決める

**しきい値** は「止まっている」と「動いている」の境目の線です。当てずっぽうで決めずに、測って決めましょう。
**だれも動いていない** ときを記録（またはシミュレーション）して、その中でいちばん大きい動きの数を見つけ、
少し余裕を足します。

```python
from csi_lab import simulate
from csi_lab.features import motion_score

_, still_motion = motion_score(simulate("still", duration_s=30, seed=1))
threshold = still_motion.max() * 1.2      # 20 % の余裕
print("しきい値 =", round(threshold, 3))
```

`seed=1` では「still」の最大値が約 0.043 だったので、しきい値は約 0.051 になりました。

## 4. お話のような記録で試す

次は、状況が **移り変わる** 記録で検出器を試します。
だれもいない → 歩く → 座って静かにする → 歩く → 手をふる → だれもいない、という流れです。
これは `data/samples/story.csv`（`uv run csi-lab samples` で作れます）と同じ流れです。

```python
import numpy as np
from csi_lab import simulate_sequence
from csi_lab.features import window_features, detect_motion

story = simulate_sequence(
    [("empty", 20), ("walk", 20), ("still", 20), ("walk", 10), ("wave", 20), ("empty", 10)],
    seed=100,
)
w = window_features(story)
motion = w.features[:, w.names.index("motion")]
predicted = detect_motion(motion, threshold=0.051)       # True = 「動いている」
truth = np.isin(w.labels, ["walk", "wave"])              # 本当に起きていたこと

print("正解率:", (predicted == truth).mean())
for label in ["empty", "still", "walk", "wave"]:
    sel = w.labels == label
    print(f"{label:6s} 窓の数={sel.sum():3d}  「動いている」と答えた割合 {predicted[sel].mean():.0%}")
```

**正解率** ＝（当たった数）÷（窓の数）です。NumPy で自分で計算しているので、魔法ではないことがわかります。

この seed では正解率は **0.87**（100 個の窓のうち 87 個が正解）でした。ラベルごとに見てみましょう。

| ラベル | 窓の数 | 「動いている」と答えた割合 |
|---|---|---|
| empty | 30 | 0 % |
| walk  | 30 | 100 % |
| still | 20 | 5 % |
| wave  | 20 | 40 % |

（シミュレーター、`seed=100`、しきい値 0.051 での結果）

## 5. うまくいかないところ ― その理由は？

- **「still」がときどき動いているように見える。** 「じっと」座っている人も、ときどき姿勢を直します。
  本物の人もそうするので、シミュレーターにはわざとこの小さな姿勢の変化を入れてあります。
  これは検出器のまちがいでしょうか？ それとも本当に何かが動いたのでしょうか？
- **「wave」（手をふる）を見のがしやすい。** 手は小さいので、はね返る電波も小さくなります。
  手をふっているときの動きの数は、座っているときより少し大きいだけです。
- **1 本のしきい値ではすべてに合わせられない。** しきい値を下げると、手をふるのをたくさん見つけられますが、
  姿勢の変化もたくさん「動いた」と言ってしまいます。ためしてみましょう！ この「あちらを立てればこちらが立たず」は、
  火災報知器や迷惑メールのフィルターなど、世の中のほとんどの検出器にある悩みです。

> **AI に聞いてみよう**
> 「わたしの動き検出器は、人がいすの上で少し姿勢を変えただけで『動いた』と言ってしまいます。
> 直すアイデアを 3 つ出して、それぞれどんな新しいまちがいが起きそうかも教えてください。」

## 6. おまけ: Wi-Fi で呼吸がわかる？

呼吸で胸が動くのは数ミリだけですが、ゆっくり、規則正しく動きます。**フーリエ変換** を使うと、
信号をいろいろなリズムに分けられます。`breathing_rate_bpm` は、その中でいちばん強いゆっくりしたリズムを探します。

```python
from csi_lab import simulate
from csi_lab.features import breathing_rate_bpm

rec = simulate("breathe", duration_s=60, seed=3)
print("1 分あたりの呼吸数:", round(breathing_rate_bpm(rec), 1))
```

シミュレーターの人は 1 分に 15 回呼吸していて、関数は 15.0 と答えました（`seed=3`）。

**気をつけること:**
- これは **シミュレーターの中だから** うまくいっています。本物の部屋ではずっと難しくなります。
  人は少しずつ動きますし、ほかの人や機械も動き、信号にも雑音が多く入ります。
- `simulate("still", 60, seed=2)` でも試してみましょう。規則正しい呼吸の動きはないのに、関数は数を返します。
  道具は必ず何かを答えますが、それが正しいとは限りません。
- これは **医療機器ではありません**。だれかの健康を調べるのには、ぜったいに使わないでください。

## たしかめよう

1. なぜパケットごとに平均で割るのですか？
2. 1 秒の窓の標準偏差が大きいとき、何が起きていると考えられますか？
3. しきい値を当てずっぽうではなく「だれも動いていない記録」から決めるのはなぜですか？
4. 検出器の正解率が 87 % でした。これはよい結果ですか？ ほかに何を知りたいですか？

<details>
<summary>答え</summary>

1. 受信機の自動利得制御が、パケットごとに音量を変えてしまうからです。平均で割るとその影響が消えて、部屋が原因の変化だけが残ります。
2. その 1 秒の間に振幅が大きくゆれた、つまり何かが動いた可能性が高いです。
3. 「止まっている」ときの数がどれくらいになるかは、部屋やハードウェアによって違います。データを見れば *この* 部屋での本当の大きさがわかりますが、当てずっぽうだと大きく外れるかもしれません。
4. 場合によります！ ラベルごとに見ましょう。どの場面を見のがしているでしょうか？ 87 % という数字の中に、ほとんどまちがえているクラス（ここでは「wave」）がかくれていることがあります。それに、試したのはシミュレーターで、本物の部屋ではありません。

</details>
