# .githooks — push されるリポジトリのハードガード

このリポジトリは **push 運用**（GitHub 等の外部リモートへ出る）。
外へ出てから気づいたのでは遅いものを、コミットの地点で止める。

## フック

| フック | 動作 | 目的 |
|---|---|---|
| `pre-commit` A | 追加行・新規パスに**機微案件名**が現れたら commit 中止 | 名前だけで案件が特定されるのを防ぐ |
| `pre-commit` B | `.local-only` 配下への**新規ファイル追加**で commit 中止 | 追跡してよいかを人が判断する地点を作る |

B はマーカーを持たないリポジトリでは自動的に何もしない。
そのため雛形をリポジトリの性質ごとに分ける必要がない
（旧 `mixed` 雛形はこれに統合した）。

## A: なぜ名前まで止めるのか

PII ガード（`~/.claude/hooks/pii-guard.py`）は**連絡先の形をした文字列**しか
見ないため、案件名は素通りする。しかし機微案件は**フォルダ名だけで
「誰の何の記録か」が特定できる**。名前は実名と同じ重さを持つ。

判定規則（`pii-guard.py` と同じ）:

- ホーム直下と、その1階層下のディレクトリを走査する
- `.local-only` を持つ、またはパスがパターンに一致するものを機微とみなす
- 名前の長さが6文字以上で、区切り記号か数字を含むものだけを対象にする
  （この条件が無いと一般語まで禁止語になり、文書で普通に使えなくなる）

見るのは**追加行と新規追加・リネームされたパスだけ**。既存行は見ない。
過去に入ったものを毎コミット蒸し返しても直せず、「いつも赤いフック」は
無視されるようになるため。過去分の始末は別途扱う。

### なぜ sh で自己完結しているか

守りたい相手は「Claude を経由しない手作業」である。`pii-guard.py` を呼ぶ
実装にすると、Python が無い環境や dotfiles 未配置のマシンで**黙って
無効化される**。効かない環境が、守りたい環境とちょうど一致してしまう。

規則が Python 側と二重になる代償は、
`claude-code-ops/scripts/test_pre_commit_names.sh` が両者の一致を
機械で検証して受け持つ。**片方だけ直すとこのテストが落ちる。**

## B: なぜマーカーだけでは足りないのか

`.local-only` は PII ガードが見る目印で、**そのディレクトリを cwd にして
作業している間**は push / remote add / gh / scp などがブロックされる。

しかし **git はリポジトリ単位で動く**。リポルートで `git push` すれば、
マーカーは効かず配下のファイルも一緒に外へ出る。
マーカーはディレクトリ単位、git はリポ単位——この粒度の差が穴になる。

既に追跡済みのファイルの更新は妨げない（運用を壊さないため）。

## 止まったときの判断

**A（案件名）で止まった場合**

- **[A] 言い換える** → 「機微リポ」「当該案件」等の一般名詞に置き換える。
  索引が要るなら機微リポ側の参照台帳に置く。
- **[B] 誤検出** → `git commit --no-verify` で通す
  （案件と無関係な同名フォルダを踏んだ場合など）。

**B（マーカー配下）で止まった場合**

- **[A] 機微情報である** → `.gitignore` に追記して追跡しない。
  ただし**除外は保護ではない**。除外した時点で保管先を決めること。
  `~/.config/crostini-backup/targets` に入っているか必ず確認する
  （入っていなければ git にもバックアップにも無い＝どこにも保存されていない）。
- **[B] 公開してよい** → `git commit --no-verify` で通す。

## 有効化（クローン／再 init 後に一度だけ）

`core.hooksPath` はリポジトリのローカル設定（`.git/config`）であり、
ファイルとしてはコミットされない。環境を作り直したら必ず再設定する。

```sh
git config core.hooksPath .githooks
chmod +x .githooks/pre-commit
```

手で戻す運用は忘れる。`claude-code-ops/scripts/install-githooks.sh` が
設置と再設定を受け持ち、`check-unprotected.sh` の検知5 が
「外れていること」を見つける。

## 有効か確認

```sh
git config core.hooksPath          # => .githooks
sh .githooks/pre-commit --list-names   # 走査で得た案件名を確認できる
```

## 注意

- **このフックに案件名・ディレクトリ名を書かないこと。** このファイルは
  push されるため、守りたい名前を守るための場所で漏らすことになる。
  名前もマーカーも実行時に `find` で走査して求めている。
- フックは `--no-verify` で回避できる。これは事故防止であって完全防御ではない。
